# linux-hardening

🇹🇷 [Türkçe](README.md) · 🇬🇧 English

Ansible-based Linux server hardening. It keeps all roles in one repository; supported distributions/versions are
listed explicitly and the playbooks **refuse to run on unsupported systems**.

**Currently supported:** Ubuntu 26.04 LTS (target: a CIS Level 1 Server approach, not a certified CIS-compliance claim).
The path to add other versions/distributions is open: see [docs/SUPPORT.md](docs/SUPPORT.md) (Turkish).

> **Language note:** the detailed guide ([HOWTO.md](HOWTO.md)), decision log ([docs/decisions.md](docs/decisions.md)) and
> most comments are in Turkish. This file is a translation of the README only.

> **Status (0.x):** **verified live** on an Ubuntu 26.04.1 LTS test VM: first-time install on a clean server, `changed=0`
> on the second run, `--check` (`failed=0`), the access-loss protections and the rollback safety net (verification
> failure, controller death, server reboot). Lynis hardening index 77, no warnings.
> **Not verified:** servers other than that one VM/configuration, a real network-level outage, Raspberry Pi/Proxmox,
> full CIS Benchmark compliance (deliberately an "approach"). Try it on a test server and take a snapshot first.

## Workflow
1. `playbooks/audit.yml` — baseline scan (Lynis)
2. `playbooks/harden.yml --check --diff` — see what would change first
3. `playbooks/harden.yml` — apply (take a snapshot/backup first)
4. `playbooks/audit.yml` — scan again and compare before/after

## Inventory group
Put your servers in the **`hardening`** group of the inventory (inventories generated by external tools can use it too).
The old **`ubuntu`** group is still accepted for a transition period. Whether a system/version is supported is checked by
`hardening_preflight`, not by the group name.

> **2FA warning:** setting `hardening_ssh_kbdinteractive: true` only flips a switch. PAM 2FA (e.g.
> `libpam-google-authenticator`) must be configured on the server separately; if it is wrong, access is lost. When enabled,
> sshd uses `AuthenticationMethods publickey,keyboard-interactive` (key AND a PAM prompt), so **password-only login** is
> not re-enabled through PAM even though `PasswordAuthentication no`. In that case the connection check only tests the
> SSH banner (a 2FA prompt cannot be answered automatically). Try it on a test server first.

## Getting started
```
python3 -m venv .venv && .venv/bin/pip install --require-hashes -r requirements.txt   # hashed, Python >= 3.12
cp inventory/hosts.example.yml inventory/hosts.yml   # write your own machines
source .venv/bin/activate
ansible-playbook playbooks/audit.yml
```

Detailed usage, sudo/production notes and troubleshooting: **[HOWTO.md](HOWTO.md)** (Turkish).
Decisions and exceptions: [docs/decisions.md](docs/decisions.md) (Turkish).

> **`hardening_ssh_allow_from` is required** (its default is intentionally empty). If it is empty, invalid, or the source
> IP Ansible connects from is not inside these networks, `harden.yml` stops without touching the firewall/SSH. You also
> cannot connect as `root`.
> Example: `-e '{"hardening_ssh_allow_from": ["192.168.1.0/24"]}'`
> Try it on a test server first, take a snapshot, and look at `--check --diff`.

## Tests
The tests under `test/` run in CI on every PR (`.github/workflows/ci.yml`); locally:

```bash
python3 -m venv .venv && .venv/bin/pip install --require-hashes -r requirements-dev.txt
PATH="$PWD/.venv/bin:$PATH" test/run-all.sh          # everything
PATH="$PWD/.venv/bin:$PATH" test/run-all.sh summary  # only tests whose name contains "summary"
```

| Test | What it protects |
|---|---|
| `test_lint.sh` | `--syntax-check`, `yamllint --strict`, `ansible-lint` (0 findings), shellcheck |
| `test_access_guards.sh` | `allow_from` empty/invalid/outside, missing `SSH_CONNECTION`, root, IPv4/IPv6 |
| `test_expressions.py` | deriving sshd ports from `ss` output, effective fail2ban `ignoreip` |
| `test_templates.py` | default template output (golden files) and safe defaults |
| `test_summary.py` | `summary.json` fields, `null` behaviour, directory/file permissions |
| `test_tags_and_hosts.sh` | preflight/guards not skipped with `--tags`, the `hardening:ubuntu` host pattern |
| `test_handlers.py` | every `notify` is bound to a handler |
| `test_vars_defined.py` | variables defined without `group_vars`, safe defaults |
| `test_consistency.sh` | `VERSION`/`component.yml`/support-matrix consistency (deliberate breakages are caught) |
| `test_release_script.sh` | `scripts/release.sh`: real signing/verification, rejection cases |
| `test_repo_hygiene.sh`, `test_ip_addresses.py` | key/token/IP leaks, package contents |

CI also tries the hashed install on Python 3.12/3.13/3.14 and runs `harden.yml --check` on a real Linux runner (`linux-smoke`).

> **Limit:** CI does not replace a live-server test; firewall/SSH changes are not applied (they would cut the runner's own connection).
> If you change the golden files on purpose: `UPDATE_GOLDEN=1 python3 -I test/test_templates.py` and review the diff in the PR.
