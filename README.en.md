# linux-hardening

🇹🇷 [Türkçe](README.md) · 🇬🇧 English

Ansible-based Linux server hardening. It keeps all roles in one repository; supported distributions/versions are
listed explicitly and the playbooks **refuse to run on unsupported systems**.

**Currently supported:** Ubuntu 26.04 LTS (target: a CIS Level 1 Server approach, not a certified CIS-compliance claim).
The path to add other versions/distributions is open: see [docs/SUPPORT.md](docs/SUPPORT.md) (Turkish).

> **Language note:** the detailed guide ([HOWTO.md](HOWTO.md)), decision log ([docs/decisions.md](docs/decisions.md)) and
> most comments are in Turkish. This file is a translation of the README only.

> **Status (0.x):** **verified live** on an Ubuntu 26.04.1 LTS test VM: first-time install on a clean server, `changed=0`
> on the second run, `--check` (`failed=0`), the access-loss protections and the rollback safety net (verification
> failure, controller death, server reboot). Lynis hardening index 77, no warnings.
> **Not verified:** servers other than that one VM/configuration, a real network-level outage, Raspberry Pi/Proxmox,
> full CIS Benchmark compliance (deliberately an "approach"). Try it on a test server and take a snapshot first.

## Workflow
1. `playbooks/audit.yml` — baseline scan (Lynis)
2. `playbooks/harden.yml --check --diff` — see what would change first
3. `playbooks/harden.yml` — apply (take a snapshot/backup first)
4. `playbooks/audit.yml` — scan again and compare before/after

## Inventory group
Put your servers in the **`hardening`** group of the inventory (inventories generated by external tools can use it too).
The old **`ubuntu`** group is still accepted for a transition period. Whether a system/version is supported is checked by
`hardening_preflight`, not by the group name.

> **2FA warning:** setting `hardening_ssh_kbdinteractive: true` only flips a switch. PAM 2FA (e.g.
> `libpam-google-authenticator`) must be configured on the server separately; if it is wrong, access is lost. When enabled,
> sshd uses `AuthenticationMethods publickey,keyboard-interactive` (key AND a PAM prompt), so **password-only login** is
> not re-enabled through PAM even though `PasswordAuthentication no`. In that case the connection check only tests the
> SSH banner (a 2FA prompt cannot be answered automatically). Try it on a test server first.

## Getting started
```
python3 -m venv .venv && .venv/bin/pip install --require-hashes -r requirements.txt   # hashed, Python >= 3.12
cp inventory/hosts.example.yml inventory/hosts.yml   # write your own machines
source .venv/bin/activate
ansible-playbook playbooks/audit.yml
```

Detailed usage, sudo/production notes and troubleshooting: **[HOWTO.md](HOWTO.md)** (Turkish).
Decisions and exceptions: [docs/decisions.md](docs/decisions.md) (Turkish).
Live verification log: [docs/verification-log.md](docs/verification-log.md); roadmap: [docs/ROADMAP.md](docs/ROADMAP.md) (Turkish).

> **`hardening_ssh_allow_from` is required** (its default is intentionally empty). If it is empty, invalid, or the source
> IP Ansible connects from is not inside these networks, `harden.yml` stops without touching the firewall/SSH. You also
> cannot connect as `root`.
> Example: `-e '{"hardening_ssh_allow_from": ["192.168.1.0/24"]}'`
>
> **Do not list only your VPN:** put **every network you may connect to the server from** in the list (VPN + LAN + ...). ufw
> allows SSH only from these networks and blocks the rest, while the guard only checks the source of the *current* connection.
> If you list only the VPN, SSH from the LAN times out (ping/ARP still work). The rollback safety net does not catch this
> either: its verification runs from the control machine, i.e. over the path that still works.
>
> Try it on a test server first, take a snapshot, and look at `--check --diff`.

## What it does not do (scope limits)

This project **does not claim full CIS Benchmark compliance**: the goal is a "Level 1 Server *approach*". Which CIS items are covered has **not yet been mapped by item number**
(the mapping will be built from the CIS Benchmark PDF, see [docs/ROADMAP.md](docs/ROADMAP.md), Turkish), so the table below is by **area**, not by item, and lists only limits verified in
the code. Rows marked "Deliberately" are documented decisions; the others are **not done yet**, which does not mean they were skipped on purpose. If you find a missing area, please open an issue.

| Area | Status | Note |
|---|---|---|
| Changing the SSH port | Deliberately not done | The ufw rule is written from the port sshd actually listens on ([decisions.md](docs/decisions.md), Turkish) |
| Automatic reboot | Deliberately not done | Automatic security updates are enabled, no reboot ([HOWTO.md](HOWTO.md), Turkish) |
| User, password and key management | Not by design | You create the user; the role only checks that `authorized_keys` is non-empty before disabling password login |
| Application hardening (nginx, MySQL, …) | Out of scope | Operating system only |
| Other distributions/versions | Not yet | Ubuntu 26.04 only; Raspberry Pi/Proxmox planned ([SUPPORT.md](docs/SUPPORT.md)) |
| Rollback | Partial | Only the sshd drop-in and ufw are rolled back; packages, sysctl, auditd, fail2ban, AIDE are not |
| Partition/mount options (`/tmp`, `nodev`, `noexec`, `hidepid`) | Not yet | |
| Bootloader (GRUB password, `audit=1`) | Not yet | Design note for `audit=1`: [auditd-kapsam.md](docs/design/auditd-kapsam.md) (Turkish) |
| AppArmor profiles | Not yet | |
| Log management (rsyslog, journald, logrotate, remote logging) | Not yet | |
| `cron`/`at` restrictions, `sudo` configuration | Not yet | `sudoers` changes are only **audited** by auditd |
| Disabling IPv6 | Not yet | |
| Core dumps | Partial | Only `fs.suid_dumpable = 0`; no `systemd-coredump` settings |
| Removing unused services/packages | Partial | Only `postfix`/`courier-*` are removed; avahi, cups, etc. are not |
| Rare filesystem modules (`cramfs`, `udf`, `squashfs`, …) | Not yet | Only `dccp`, `sctp`, `rds`, `tipc` and `usb-storage` are blocked |
| SUID/SGID inventory | Not yet | |
| Scheduled AIDE checks | Not yet | Only the initial database is created; scheduling is the package default (not verified) |
| Time synchronization | Partial | Read-only report only (`hardening_time`: clock-drift warning); chrony is not configured. Design note: [zaman-ntp.md](docs/design/zaman-ntp.md) (Turkish) |
| Audit (auditd) coverage | Limited | 6 rule groups (`identity`, `scope`, `sshd`, `logins`, `time-change`, `modules`); no `-e 2`; command execution/file deletion are not audited; processes started **before** auditd are not audited until restarted |
| fail2ban | Limited | `sshd` jail only |

Known conflicts (places where hardening can break legitimate use): [docs/known-issues.md](docs/known-issues.md) (Turkish).

## Tests
The tests under `test/` run in CI on every PR (`.github/workflows/ci.yml`); locally:

```bash
python3 -m venv .venv && .venv/bin/pip install --require-hashes -r requirements-dev.txt
PATH="$PWD/.venv/bin:$PATH" test/run-all.sh          # everything
PATH="$PWD/.venv/bin:$PATH" test/run-all.sh summary  # only tests whose name contains "summary"
```

| Test | What it protects |
|---|---|
| `test_lint.sh` | `--syntax-check`, `yamllint --strict`, `ansible-lint` (0 findings), shellcheck |
| `test_access_guards.sh` | `allow_from` empty/invalid/outside, missing `SSH_CONNECTION`, root, IPv4/IPv6 |
| `test_expressions.py` | deriving sshd ports from `ss` output, effective fail2ban `ignoreip` |
| `test_templates.py` | default template output (golden files) and safe defaults |
| `test_scan_dir.py` | The scan directory defaults to the user folder (HOME/XDG), never the package folder; modes 0700/0600; stops without HOME |
| `test_summary.py` | `summary.json` fields, `null` behaviour, directory/file permissions |
| `test_tags_and_hosts.sh` | preflight/guards not skipped with `--tags`, `hardening`/`ubuntu` group selection and no warning for a missing group |
| `test_facts_namespace.sh` | Facts are read only via `ansible_facts[...]` (OS check under `INJECT_FACTS_AS_VARS=False`), ban on top-level fact names |
| `test_cis_quickwins.py` | CIS quick wins: module lists, ufw `routed` policy, `audit=1` (real `replace` module, idempotent), ssh restart refusal, risky options default to off |
| `test_time_report.py` | time report decision (real `chronyc -c sources` format): healthy, stale/skewed clock, service down, no sources, threshold, malformed lines |
| `test_time_tasks.py` | the time role stays read-only: read-only modules only, works in `--check`, can be disabled, no command changes the clock |
| `test_ufw_stale_rules.py` | ufw stale SSH rule decision: network normalization, controller/empty allow_from/extra_allow safeguards, missing-rule detection |
| `test_ufw_prune_tasks.py` | structure of the ufw delete tasks: off by default, never deletes in `--check`, post-delete verification before ufw enable |
| `test_auditd_unaudited.py` | read-only detection of processes started before auditd (fake `ps`/`systemctl`); kernel threads and threshold excluded |
| `test_auditd_rules_order.py` | auditd rules are loaded right after the service starts (not via a handler at play end) and skipped in `--check` |
| `test_handlers.py` | every `notify` is bound to a handler |
| `test_vars_defined.py` | variables defined without `group_vars`, safe defaults |
| `test_consistency.sh` | `VERSION`/`component.yml`/support-matrix consistency (deliberate breakages are caught) |
| `test_release_script.sh` | `scripts/release.sh`: real signing/verification, rejection cases |
| `test_repo_hygiene.sh`, `test_ip_addresses.py` | key/token/IP leaks, package contents |

CI also tries the hashed install on Python 3.12/3.13/3.14 and runs `harden.yml --check` on a real Linux runner (`linux-smoke`).

> **Limit:** CI does not replace a live-server test; firewall/SSH changes are not applied (they would cut the runner's own connection).
> If you change the golden files on purpose: `UPDATE_GOLDEN=1 python3 -I test/test_templates.py` and review the diff in the PR.
